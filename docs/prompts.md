# AI Prompt 记录

## 2026-09-25：需求与计划

用户要求：从零用 Go 实现最小可用 Agent，禁止使用现有 Agent 框架完成主流程；需要基本循环、至少三个带 Schema 的工具、独立 session、上下文管理与压缩、异常处理、工具 trace、测试用例、真实 LLM API、README 及开发记录。随后要求把实现计划写入项目文件并开始第一阶段。

本次开发采用的实现约束：Runtime、工具注册、上下文选择和解析逻辑由本项目实现；SQLite 驱动只负责持久化，不提供 Agent 行为。第一阶段只建立可运行骨架，不提前把未实现的聊天接口伪装为可用。

每次 AI 辅助开发记录日期、目标、关键 Prompt、产出及人工核验结果。不要在此文件粘贴 API Key 或其他秘密。

## 2026-09-25：第二阶段实现

用户 Prompt：“继续完成下一阶段的内容。”随后明确：“你先创好相关文件，后续我手动配置密钥，然后再测试连通性。你先把理论的代码弄好。”

产出：自行实现工具注册与 Schema 校验、四个工具、Responses API HTTP 客户端、输出解析、Agent 循环、聊天接口、工具 trace 和假 LLM 测试；提供 `.env.example` 及真实 API 冒烟测试脚本。按照用户要求，真实 API 连通性留待密钥配置后验证。

## 2026-09-25：第三阶段实现

用户 Prompt：“完成第三阶段的内容。”

产出：按 session 串行处理请求；在每轮开始召回摘要和未压缩的近期完整轮次；超过阈值时用 LLM 把较早已完成轮次压缩为摘要，并持久化摘要覆盖的消息 ID。原始消息不删除。测试覆盖纯对话和工具追问、两个窗口、旧数据库升级及重启恢复。
